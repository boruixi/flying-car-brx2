00Executive Summary

执行摘要

  1. EH216-S 的安全基线建立在分布式多旋翼与全冗余架构上：8 轴 16 旋翼独立驱动，飞控、传感器、动力、电池等关键部件采用多套备份，多套飞控带投票机制，内置 Fail-Safe 健康监测，可判断续飞或就近应急降落[1][8]。
  2. 安全目标应与运行场景绑定。参照 EASA SC-VTOL Enhanced 类量级，灾难性失效状态概率目标约为 ≤10⁻⁹/飞行小时，且单点失效不得导致灾难性后果[4][5]；EH216-S 按中国民航局专用条件审定，具体安全目标以局方文件为准。
  3. 主要风险集中在四条链路：推进与能源（多桨失效、电池热失控）、飞控与导航（传感器冲突、链路中断、定位失锁）、外部环境（鸟击/FOD、阵风与风切变）、地面第三方（坠落与桨下气流）。
  4. 已披露的是“冗余与处置策略”，定量安全证据披露有限：公开材料说明了备份接管、Fail-Safe 与自动返航，但失效概率、软件保证等级、电池热失控试验、共因分析（CCA）细节未完整公开。
  5. 安全闭环不止于飞行器本体：场地净空与人员隔离、气象窗口、维修与人员资质、应急消防、保险与事故责任，属于运行安全体系，和单机冗余同等重要。
  6. 结论分层：受控场地内的低空观光运行，现有冗余与处置措施提供了可接受的初步安全基础；向城市通勤、开放空域扩展时，必须补齐定量安全评估、环境适应性与第三方风险证据。

01Scope, Boundary and Safety Objectives

分析对象、系统边界与安全目标

安全分析先划清系统边界：哪些在航空器内部，哪些属于地面与外部环境；再在边界上定义安全目标与约束。

航空器本体

  • 机身结构与座舱约束
  • 8 轴 16 旋翼与电机
  • 电池组、配电与 BMS
  • 飞控、传感器与导航
  • 通信链路与机载计算机

地面与运行侧

  • 地面控制站与调度系统
  • 起降场地与净空隔离区
  • 运维、维修与充电保障
  • 操作员/地面监控人员
  • 气象与空域管理支持

外部与第三方

  • 地面人员与建筑物
  • 鸟击、FOD 与低空障碍物
  • 风、阵风、风切变、降水
  • 其他低空航空器
  • 噪声与桨下气流影响

1.1 安全目标与失效严重度分级

参照民用航空器安全性评估惯例与 SC-VTOL 的失效状态分类，后果由轻到重分为：轻微（无伤害）、轻（轻微伤害）、重（较重伤害）、严重（乘员重伤）、灾难性（乘员死亡或航空器损毁）。安全目标通常按“失效状态严重度 × 发生概率”设定，并要求单点失效不得上升为灾难性后果[4][6]。

失效状态等级典型后果参照概率目标（SC-VTOL Enhanced）对应开发保证等级（参照）
灾难性 Catastrophic乘员死亡 / 航空器损毁≤ 10⁻⁹ / 飞行小时FDAL A
危险 Hazardous乘员重伤、安全裕度显著下降≤ 10⁻⁷ / 飞行小时FDAL B
较大 Major乘员轻度不适、工作负担增加按等级相应放宽FDAL C / D
轻微 Minor / 无影响无安全影响，仅便利性下降—FDAL E

概率与等级为国际标准参照量级，用于建立分析框架；EH216-S 的审定安全目标以中国民航局专用条件及批准文件为准[2]。

02Safety Process and Lifecycle

系统安全工程流程与全寿命周期

系统安全不是末端检查，而是贯穿研制全周期的闭环。参照 ARP4754A 开发保证与 ARP4761 安全性评估方法，安全活动从概念阶段一直延伸到运行与退役[6][7]。

阶段 1
概念 / FHA
功能危害性评估，识别顶层失效状态，设定安全目标。
阶段 2
研制 / PSSA
初步系统安全性评估，分配冗余与安全需求，做架构与共因分析。
阶段 3
验证 / SSA
系统安全性评估，FTA/FMEA、故障注入与试飞验证需求闭环。
阶段 4
生产
PC 体系下的一致性制造、零部件追溯与质量控制。
阶段 5
运行
OC 下的航线运行、健康监控、维修规程与人员资质管理。
阶段 6
退役 / 回收
电池与结构件回收、故障数据反馈与设计改进。

方法链路上，FHA 自上而下给出顶层危险，PSSA 在方案阶段把安全需求分配到子系统，SSA 在设计冻结后验证所有安全需求是否被满足；FTA、FMEA、CCA 等工具贯穿其中。安全案例（Safety Case）则把目标、证据、假设和残余风险组织成一份可审查的论证文件。

风险处置原则
按优先级：规避（改航线/改场景避开危险）→ 降低（冗余、检测、防护措施）→ 转移（保险、第三方责任）→ 接受（在可接受标准内并记录残余风险）。不可接受等级的风险必须在设计或运行层面对策落地后，才能重新评估。
05Safety Design and Redundancy

安全性设计与冗余架构

EH216-S 公开披露的安全设计可归纳为四层冗余：硬件部件、飞控系统、飞行处置与通信调度。冗余的价值取决于独立性——共因失效会让“纸面冗余”失效。

层级设计措施（公开披露）安全作用需验证的问题
硬件冗余飞控、传感器、动力、电池及 BMS 多套备份，故障时无缝接管[8]单点硬件失效不中断关键功能备份切换时间、切换瞬间姿态扰动
系统冗余多套飞控 + 投票机制，多传感器交叉校验[1]识别并剔除异常通道，避免错误指令投票逻辑独立性、传感器共模偏差
飞行处置Fail-Safe 实时监测健康状态，判断续飞或就近应急降落；自动返航[9]故障后进入可控状态，避免不可控坠地迫降区选择、剩余能量与着陆冲击
推进冗余16 副桨各配独立电机，单/多桨停转时其余补推力；展会采访口径极端情况下部分桨停转仍可安全降落[9]用分布式动力吸收推进失效可容忍失效桨数与包线（媒体口径，非审定指标）
救生设备整机降落伞作为最后手段（公开资料提及）失控/失去动力时降低坠落速度开伞高度、姿态与地面人群规避
通信调度4G/5G 链路与地面指挥调度实时联动，地面监控与预警[1]地面侧掌握状态并介入处置链路中断后的自主续飞边界
冗余独立性是关键
两套备份若共用同一电源、同一软件库、同一线束走向或同一传感器批次，一个共因事件可能同时打掉两条通道。因此冗余架构必须配合共因分析（CCA），见第 06 节。
06Safety Analysis Methods

安全性分析方法：FMEA / FTA / ETA / CCA

下面用四类经典方法对 EH216-S 做教学性演示。表格与树状图用于说明分析思路，数值为定性判断，不替代正式审定报告。

6.1 FMEA / FMECA：自下而上的失效模式分析

系统 / 功能失效模式局部影响高层影响补偿措施残余风险
旋翼 / 电机单桨停转该方向升力轻微损失姿态轻微偏差其余旋翼补推力、飞控重分配低

6.2 FTA 故障树：自上而下追溯顶层危险

以顶层事件“乘员伤亡或航空器损毁”为顶，向下分解为四类中间事件，再追溯到底层失效事件（定性或门）。

顶层事件：乘员伤亡 / 航空器损毁

A 失去升力 / 推力

  • 单/多桨失效
  • 电机卡滞或烧毁
  • 电池支路断电
  • 推力不对称失控

B 飞行失控

  • 飞控通道失效
  • 传感器数据冲突
  • 导航失锁 / 偏离
  • 软件逻辑缺陷

C 外部撞击 / 环境

  • 鸟击 / FOD
  • 阵风 / 风切变越界
  • 障碍物 / 他机冲突
  • 结冰或恶劣天气

D 火灾 / 危险品

  • 电池热失控
  • 配电线路漏电
  • 可燃物引燃蔓延

6.3 ETA 事件树：从始发事件看处置路径

始发事件
任一关键系统失效（推进 / 能源 / 飞控 / 链路）
探测与告警
健康监测是否识别异常并告警？
冗余接管
备份通道是否成功接管、维持可控姿态？
安全路径
可控续飞 → 返航或就近应急降落 → 安全着陆
失败路径
接管失败 → 应急迫降 / 开伞 → 残余坠地与第三方风险

6.4 CCA 共因分析：验证冗余是否真独立

子方法分析内容在 EH216-S 上的关注点
区域安全性分析 ZSA按设备布置区域，评估线束、管路、设备间的相互影响桨叶爆裂打击路径、线束分区、相邻设备隔离
特定风险分析 PRA评估外部/特定危险对冗余系统的叠加影响鸟击、FOD、物体脱落、火灾蔓延对备份通道的影响
共模分析 CMA排查冗余通道共享的失效机理共用软件库、电源、传感器批次、维修程序与设计错误

CAAC 无人驾驶航空器系统安全性分析指南要求：针对所有灾难性失效状态开展共因分析，确保不会由单点失效导致灾难性后果[3]。

07Functional Safety and SOTIF

功能安全与预期功能安全（SOTIF）

功能安全关注“硬件/软件故障导致的危险”，SOTIF 关注“没有故障、但功能本身不足或被误用导致的危险”。对自动驾驶航空器，后者尤其重要；两类方法分别对应 ISO 26262 与 ISO 21448 框架[12]。

类别关注问题EH216-S 相关场景应对方向
功能安全（ISO 26262 思路）电气/电子系统故障是否引发危险飞控、电机、BMS、传感器失效冗余、诊断、降级、安全状态设计
预期功能不足感知/决策/控制能力在边界条件下不足雨雾、弱光、城市峡谷、复杂风场下的感知与导航场景测试、性能边界标定、运行环境限制
可预见误用乘客或操作员可合理预见的错误使用乘客误触、超气象窗口飞行、违规配载互锁、规程、提示与权限限制
人机与监控地面站对状态理解与介入时机长时监控疲劳、异常确认延迟告警分级、操作流程、人员培训

SOTIF 的核心是识别“系统没坏、但工况超出能力”的情形，并用场景设计、限制措施和验证证据把风险降到可接受水平。对无人驾驶载人航空器，感知可靠性、模式边界理解和异常处置，与硬件故障同等重要。

08Airworthiness and Operational Safety

适航审定与运行安全

单机安全要进入合法运行，还需通过适航审定与运行许可两道关口，并在场地、人员、应急和维修层面建立运行安全体系；安全等级最终是在审定与运行过程中“审”出来的，而不是由宣传口径给出[10]。

8.1 审定资质链

资质含义对安全的意义
型号合格证 TC型号设计经审定符合安全要求证明设计方案满足专用条件与安全目标
生产许可证 PC具备按批准设计稳定批量制造的能力[11]保证每架飞机制造一致性与质量可控
标准适航证 AC单架航空器符合批准型号、可安全飞行架级合格，允许投入使用
运营合格证 OC运营主体具备载人运行的人员、规程与保障能力把单机安全延伸到组织化运行安全

专用条件对关键系统给出了明确要求，以电池与配电系统为例：需向远程机组提供剩余可用电能的判断措施，保证正常工作时不间断供电；提供电池安全移除或隔离的措施；防止漏电，并降低可生存应急着陆期间对乘员的危害[2]。

8.2 运行安全要素

  • 场地与第三方风险：起降点净空、隔离区、地面人员管控、迫降落点预判，控制坠落与桨下气流对第三方的影响。
  • 气象与环境限制：明确风速、降水、能见度、温度与昼间运行边界，超限即停飞。
  • 人员与规程：地面监控人员培训与资质、标准操作程序、应急处置流程、交接与值班管理。
  • 维修与健康监控：旋翼/电机/电池检查周期、故障记录、寿命件管理、维修差错防控。
  • 应急与保险：现场消防、乘员撤离、事故报告流程，以及第三方责任保险与事故责任界定。
09Residual Risks and Open Questions

残余风险与未决问题

结合公开信息，以下安全证据目前披露有限，属于需要持续追踪的未决项；在证据补齐前，应在运行限制与风险接受结论中保留不确定性。

  • 定量失效概率：灾难性/危险失效状态的概率指标、可靠性数据与维修间隔未完整公开。
  • 软件保证等级：飞控与决策软件的开发保证等级、验证覆盖度与独立审查情况未见详细披露。
  • 电池安全：热失控抑制、针刺/挤压/过充试验、低温与循环衰减下的安全边界证据不足。
  • 冗余裕度：可容忍的失效桨数、失效后姿态保持与迫降能力，公开口径多为媒体采访，需审定数据支撑。
  • 共因与特定风险：ZSA/PRA/CMA 分析报告、桨叶爆裂与鸟击撞击试验细节未公开。
  • 环境适应性：高寒、高温、高湿、雨雾与城市峡谷条件下的感知、导航与动力表现需更多运行数据。
  • 第三方地面风险：人口密集区上空运行的坠落风险评估、噪声与社会接受度证据仍在积累。
10Safety Improvement Gates

安全改进建议与门槛

从安全工程角度，建议按四个门槛补齐证据；任一门槛缺少可审查证据，都应在场景与运行范围上保留限制。

GATE 1
定量安全评估
给出失效状态概率、冗余裕度与故障注入试验结果，闭合 FTA/FMEA。
GATE 2
能源与结构安全
电池热失控、环境适应性、桨叶强度与撞击（鸟击/FOD）试验证据。
GATE 3
共因与软件独立性
完成 CCA 三项分析，验证冗余通道独立性与软件保证等级。
GATE 4
运行安全闭环
场地隔离、气象窗口、人员资质、维修规程、应急与保险体系可审查。

对课程研究而言，最稳妥的表述是：EH216-S 在受控低空观光场景下，已通过适航审定并建立了多层冗余与处置策略，具备初步运行安全基础；面向更开放、更高密度的场景，安全结论必须等待定量证据与运行数据的进一步积累。
